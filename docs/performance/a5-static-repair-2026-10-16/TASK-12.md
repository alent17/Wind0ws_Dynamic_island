## 真实失败依据

第 11 批单次正常会话停在前置，161 次 Enqueued/nativeApplied=false/nativeReady=false，测试 move/down/up=0，事件监听/Canvas/截图/坐标冻结均未到。根因尚未确证，不写成 OS 输入或 SetWindowRgn 失败。恢复遭遇 Studio 自动新增 playerOrderIds 与全快照断言冲突、无公开恢复入口、ISO 自动 DateTime 转换、File.Replace 空字符串绑定，以及数字 PID 不能区分原代次的问题。原配置/Run 已于 10 月 16 日按原字节恢复并被独立读回；旧进程已不在，但历史前台/光标和退出过程缺记录。旧原始证据、失败及私有备份保留。

## 仅返修这些边界

1. **把静态 lab 的初始化做成可靠且可观察的一次协议。** 在原 feature-only 适配器内记录 loaded/configured/queued 及有限初始化阶段/失败原因，能区分未收到文档完成、配置未完成、派发失败和实际应用失败。调用顺序已核对并纠正：锁定 wry 的 attach_handlers 约在 webview2/mod.rs:466 先执行，首次 Navigate 约在 531；642–665 是被调用函数体的定义位置，不能据此推断注册晚于导航。此前这一候选撤回，现场持续 Enqueued 的根因仍未确认。选择经依赖源码/官方 API 语义支持的最小一次初始化方法，保证对应本代次文档及 HWND，不直接把 loaded=true、延长等待或删掉就绪门。若需显式首次导航/文档标识，事件过滤、导航白名单与协调器页定位需共同匹配，旧文档/重载不得使新代次就绪。不要扩为产品主岛接入、动画、全局 hook、composition 或窗口架构改造。

2. **修正真实持久恢复路径。** 第 10 批 helper 中 File.Replace 的 `$null` 绑定同样有缺陷，修复实际共享调用，使用独立临时文件真实验证替换/源消费/目标 hash 及失败保留，不只写 fake。若处理 ISO 或进程代次，明确保留完整字符串与 100ns，按实例而非 PID 数字/旧 HWND 是否存在判断，不操作复用身份。冻结的第 11 批恢复脚本和失败包作为历史留存，不把新通用策略强塞回原记录。

3. **处理本工具自己触发的 Studio 设置写入。** 继续保存不可变的启动前磁盘备份；为新建 Studio 的正常会话发现/保存取得可审计的调用与结果依据，形成明确的预期变更记录。不要把全部 playerOrderIds 差异或未知设置写入一律忽略，也不能将新出现的设置变化都归因用户。未知键、未知顺序变化、其他写入者仍停止。严格区分原始状态、已审自动/工具变更、当前实际状态，恢复后的两原始文件及 Run 必须实际回读一致。

4. **给 pending 模式一个真实的“只继续清理”入口。** 复用实际 Node/PS 传输与恢复函数，保留原 session/代次、已完成步骤和限次。不得用永不恢复的 Promise 单独维持进程却无法关闭；控制入口不能重开测试、重置 4 次预算、重新选点或执行任意命令。只在 ownership 已确认释放且新物理 idle/身份/设置门通过时续做未完成的恢复阶段；已知释放失败不重复 SendInput，不盲目重做已经关闭/退出的步骤。正常收尾应确认工具窗口、测试应用、helper/coordinator 退出并保存结果，禁止硬杀/调试/跨进程句柄操作代替协议。EOF、断管或已退出的传输如确实无法恢复，应明确仅持久恢复的安全边界，不操作跨日旧前台/光标句柄。
