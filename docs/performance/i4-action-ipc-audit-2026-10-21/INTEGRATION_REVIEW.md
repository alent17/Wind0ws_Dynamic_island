## Confirmed integration fixes in this review

1. A volume write failure previously cleared the latest pending value as well as the failed write. The queue now continues with the newest pending value, retaining its dedupe key; when no newer value exists, the failed key clears so the user can retry. App only refreshes native volume after an unreplaced failure, and skips that recovery read after disposal or during device switching.
2. A device switch previously invalidated dedupe but left a pending old-device value that could dispatch against the new default endpoint. It now cancels pending writes at switch start and ignores slider submissions during the switch; the new device read invalidates dedupe again on completion.
3. `FLOATING_MEDIA_NOT_READY` carried `appSessionId`, but App ignored it. A delayed old-session notification with a still-current instance token could pause the current relay. App now ignores mismatched tagged sessions and keeps compatibility for legacy untagged events.
