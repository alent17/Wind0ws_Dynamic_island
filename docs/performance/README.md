# 顶部工具栏与页面释放验证（2026-09-26）

## 常驻窗口补充修复

启动配置只创建主灵动岛。Studio 和独立倒计时改为按需异步创建，关闭时销毁 WebView；Studio 的功能栏切换关闭也走保存后销毁流程。此前仅卸载 DOM，没有移除配置中预创建的两个隐藏 WebView，因此仍会保留运行时内存。此项修改需要运行新版本的原生程序才生效。

功能栏由 72px 缩为 40px，使用 28px 点击区、16px 图标，移除可见名称。主界面仍依赖 WebView2，彻底移除需要替换现有 Svelte 界面层。本次没有声称消除 WebView2 基础占用，也没有新的原生内存降幅测量。

## 已实现

- 展开岛内顶部工具栏，最多同时显示五项，横向浏览七项；时间、天气在末尾。
- 页面替换时只保留一个页面实例，旧页面淡出 100ms 后卸载，快速切换取消过期计时。收起后卸载展开内容。
- 长标题使用渐变和往返 transform 动画，24px/s、两端停留 1.2 秒；销毁时取消动画并断开 ResizeObserver。
- 隐藏辅助窗口卸载内容；Studio 关闭前保存设置并销毁窗口。晚到的监听器立即释放，独占 HTTP 请求中止，图片与 RAF 清理。
- 频谱按页面计数，并在后端按窗口记录消费者，最后一个消费者离开才停止。窗口销毁也释放记录。
- 媒体共享请求防重入，旧回调丢弃；天气请求合并，缓存只保留一个城市；封面缓存限制 64 条、8MiB URL 数据并清理过期条目。
- 时钟按分钟边界更新，音乐可见播放时 250ms 更新，运行中的倒计时 1s 更新。

## 页面性能采样

同一台机器、同一 Chrome headless、生产构建测试页；每场景预热 5 秒，采样 60 秒。CPU 是 CDP TaskDuration / 实际经过时间，约等于单核渲染任务占用，不包含 GPU/浏览器进程。JS 堆不是进程私有内存，也不是工作集。

前版五种工具，后版新增时间和天气，默认七种工具；音乐展开页和详情页多了顶部工具栏。采样期间机器还有构建/测试活动，因此不能把小幅差异判定为稳定收益。采样版本包含主要页面卸载与工具栏改动，之后还有生命周期清理修正。

| 场景 | 渲染任务 CPU %（前 → 后） | 结束 JS 堆 MiB（前 → 后） | DOM 节点（前 → 后） |
|---|---:|---:|---:|
| paused-compact | 0.029 → 0.078 | 2.54 → 2.43 | 767 → 270 |
| playing-compact | 8.377 → 7.663 | 3.65 → 3.40 | 764 → 270 |
| music-expanded | 7.771 → 9.068 | 3.53 → 3.59 | 762 → 935 |
| volume-detail | 0.025 → 0.037 | 3.56 → 3.47 | 906 → 1075 |
| unmounted | 0.024 → 0.031 | 2.44 → 2.36 | 9 → 9 |

`unmounted` 是导航到空白页的释放基线，不等同于原生窗口隐藏。收起场景 DOM 减少约 65%；本次数据无法证明展开页 CPU 下降，也不能证明原生总内存下降。

## 重复切换保留量

使用生产构建（关闭开发期 HMR 和组件调试追踪），预热 5 次后循环 30 次“音量→音乐→收起→展开”，两端均执行 GC：DOM 1002→1002，监听器 53→53，JS 堆 3,330,136→3,690,032 字节。未出现按切换次数累积的 DOM/监听器。脚本 `scripts/measure-retained-memory.mjs after` 保留了自动断言与原始数据。

开发模式同一测试会保留大量调试节点，不能用于生产内存结论。已改用相同交互的生产构建采样确认。

## 原生测量限制

保存了现有运行中的 Isle 主进程及所属 WebView 子进程共 60 秒的观测数据（native-before.json）。场景没有受控，运行的是已有 debug 程序，不作为新版对照。

尚未完成计划要求的新版原生五场景 CPU、私有内存、工作集逐项对照，以及原生窗口反复开关的长期内存曲线。因此不宣称已通过这些性能验收。浏览器 DOM/动画释放测试不能替代该验收。

## 活跃频谱渲染采样（2026-09-30）

修正后的播放夹具为紧凑播放和展开音乐页开启动态合成频谱；旧夹具启用了减少动画，不能代表正在播放时的频谱负载。新采样连续 60 秒，记录在 `live-spectrum-2026-09-30.json`。

| 场景 | 渲染任务 CPU | 结束 JS 堆 | DOM 节点 |
|---|---:|---:|---:|
| playing-compact | 0.636% | 3.11 MiB | 950 |
| music-expanded | 0.634% | 3.19 MiB | 923 |

这组结果低于 1%，但只表示 Chrome 测试页渲染线程的 TaskDuration；频谱数据是合成的，不包括 Rust 音频采集、WebView2 子进程/GPU，也不能证明整个程序 CPU 低于 1% 或工作集低于 100 MiB。原生进程指标仍需在播放真实音乐的 Isle 实例上采样。

可用环境变量选场景和采样时长：

```powershell
$env:PERF_SCENES='playing-compact,music-expanded'
$env:PERF_SAMPLE_SECONDS='60'
node scripts/build-performance.mjs live-spectrum
node scripts/measure-performance.mjs live-spectrum
```

## 1.0.8 频谱平滑与开销对照（2026-09-30）

本次同场景各采样 30 秒，动态合成频谱保持开启。旧渲染对照使用 HEAD 中的 `Spectrum.svelte`（24 Hz），其他模块保持当前代码；合成频谱不使用原生采集。原始记录包含旧渲染、放弃的逐帧 RAF 方案和最终方案，见 `spectrum-1.0.8-2026-09-30.json`。

| 场景 | 旧渲染 CPU | 最终渲染 CPU |
|---|---:|---:|
| playing-compact | 1.113% | 0.981% |
| music-expanded | 1.025% | 0.934% |

最终方案使用 30 Hz 定时绘制、按时间平滑柱高、固定不透明度，并将同色柱子合并填充。逐帧添加 RAF 的尝试在本轮采样达到约 1.96–2.26%，因此未采用。最终 JS 堆约 2.66/2.77 MiB，与本次旧渲染对照基本一致；不能据此宣称整体内存下降。

原生音频复用 FFT scratch，静音窗口跳过 FFT 但保持原有释放包络；前端复用随机频谱和共享采集数组。这些减少临时分配，不代表已验证整个应用的私有内存或 CPU 目标。上述数据只覆盖测试页渲染，且不能与之前不同运行条件下的数值直接比较。

## 1.0.8 安装版真实进程采样

用户确认场景为播放音乐、紧凑模式。确认运行文件是 `E:\Isle\isle.exe`，版本 1.0.8；其进程树只有一个页面 renderer，调试 FPS 未开启。使用 `scripts/measure-native.ps1 -Seconds 20 -Label native-1.0.8-playing-compact`，按逻辑核心数归一化进程 CPU，并读取结束时私有工作集。原始数据见 `native-1.0.8-playing-compact.json`。

| 进程 | 平均 CPU | 私有工作集 |
|---|---:|---:|
| Isle | 0.320% | 13.41 MiB |
| WebView2 browser | 0.090% | 35.92 MiB |
| WebView2 GPU | 0.490% | 47.98 MiB |
| WebView2 renderer | 0.431% | 65.50 MiB |
| 其余 WebView2 服务 | 约 0% | 10.72 MiB |

这不是 1.0.9 的验收结果。1.0.9 增加不可见频谱高度变化的绘制合并、窗口模块按需加载、有限封面动画结束后解除填充状态。其效果需要安装新版后同场景采样，不用 Chrome 测试页数据替代，也不宣称已达到整组 1% CPU / 100 MB 内存。

## 1.0.9 安装后现场观测

已备份旧程序，通过本地 NSIS 安装包将 `E:\Isle\isle.exe` 更新并重启为 1.0.9，核对安装目录文件的版本。用户设置沿用。安装目录 EXE 与构建目录 EXE 的哈希不同，不能宣称两者逐字节一致。

| 采样 | 整组平均 CPU | 结束私有工作集 |
|---|---:|---:|
| 启动后预热 15 秒，再采样 20 秒 | 0.793% | 131.23 MiB |
| 随后采样 60 秒 | 0.134% | 165.06 MiB |

原始记录见 `native-1.0.9-playing-compact.json` 与 `native-1.0.9-playing-compact-60s.json`。复测后只读查询系统媒体会话，报告 `cloudmusic.exe: Playing`；只读检查显示 Isle 宿主窗口可见，用户随后确认紧凑模式下频谱正常变化。采样全程的窗口模式、播放状态和频谱运动没有自动记录，仍不是受控的跨版本验收对照，也不保证任意场景或瞬时峰值低于 1%。

前后音乐时段、应用运行时长及缓存状态不同，不据此计算严格性能改善百分比。内存会在预热后增加，131 MiB 不是长期上限；整组 100 MB 目标仍未达到。

## 1.0.10 悬浮窗样式修复

1.0.9 的条件动态导入经生产构建后，共用了计时器的 CSS 预加载依赖列表。悬浮窗组件虽然挂载，但缺少其布局样式。将两个窗口的动态导入拆入独立函数，保留窗口模块按需加载和之前的音频、频谱优化。

新增 `node scripts/verify-window-styles.mjs`（先执行 `npm run build`）验证实际生产页面：悬浮窗、计时器各加载自己的 CSS，且不加载对方的 CSS；悬浮窗的定位、深色背景和窗口宽度符合原有布局。浏览器测试不验证原生媒体控制和 Windows 窗口行为。
