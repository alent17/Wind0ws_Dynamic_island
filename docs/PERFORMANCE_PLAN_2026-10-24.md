# Isle 整体优化与测试计划

日期：2026-10-24。目标：保留当前功能与动画体验，整棵应用进程树常驻内存低于 100 MB。

## 1. 验收口径

采用十进制 100 MB（100,000,000 字节），不是仅统计 isle.exe，也不是只统计 JavaScript 堆。主指标为应用及所有子进程的**私有工作集**；同步报告私有提交量、峰值、P95、CPU、句柄和线程数。提交量和共享工作集不能与私有工作集混用。

默认按严格目标处理：待机、播放、展开、设置、悬浮播放器、计时器及其组合场景都需满足。启动和切歌瞬时峰值单列，不能通过周期性清空工作集掩盖真实分配。任何场景超标都不能宣称整体达标。

正式内存验收：每场景预热 5 分钟，采样 10 分钟，至少重复 3 次。CPU 对照测试必须避开编译和其他压测；保留系统版本、DPI、WebView2 版本、设置摘要、二进制哈希和进程树。短测只用于定位。

动画验收：不改变现有展开/收起时长、弹性曲线、封面交接与频谱节奏。60 Hz 环境下对展开、反向切换、悬浮唱片、切歌、工具页逐项采集帧间隔；建议 P95 ≤ 20 ms、P99 ≤ 33.4 ms，不得出现重复的 >50 ms 停顿。120/144 Hz 另列结果，不把当前 30 Hz 频谱采样误判为整个 UI 掉帧。浏览器 rAF 只能诊断主线程节奏，最终显示需 PresentMon/ETW 证据。

## 2. 程序结构与主要开销

| 层 | 现状 | 优化重点 |
| --- | --- | --- |
| Rust/Tauri | 窗口、托盘、设置、媒体 actor、Win32 监测 | 有界任务队列、减少重复系统查询、退出与取消 |
| WebView2 | 浏览器、GPU、网络、渲染器等子进程 | 独立量化基础运行成本、页面存活数、合成表面 |
| Svelte UI | 主岛、Studio、悬浮播放器、计时器 | 只让可见消费者工作，限制图片和 DOM 保留 |
| 图片链路 | 下载、缓存、校验解码、缩放、像素化、取色 | 输入字节/解码像素/并发预算分别控制 |
| 音频频谱 | WASAPI、2048 点 FFT、六段频谱、Canvas | 不改音效表现；检查隐藏、静音、切设备与重启 |

现有实现已经具备按需创建 Studio、动态加载窗口组件、有界封面结果缓存、媒体版本戳、取色取消、频谱变化过滤与静音跳过 FFT。这些应保留，不能把它们列为本轮新增收益。

## 3. 分阶段执行

### P0：建立可信基线（本轮已执行短测）

1. 运行前端单元测试、Svelte 检查、Rust 测试及 Playwright 功能测试。
2. 用 `custom-protocol` 编译 Release，禁止用 Vite 开发模式内存代表产品内存。
3. 对显式 RootPid 采集完整子进程树，按角色定位 Rust、browser、renderer、GPU 的分配。
4. 保存生产夹具五种场景的页面 CPU/堆，以及 30 轮展开/工具页切换后的 GC 保留量。
5. 新增严格内存门禁，缺失计数器、缺失根进程或超预算均失败。

### P1：资源生命周期和图片峰值（本轮已实施）

- CoverArt 使用可取消、5 秒超时的预加载。切歌、清空封面、卸载取消旧请求；成功后释放预加载源，只由 DOM 双槽负责显示和 220 ms 淡入淡出。加载失败保留最后一张成功封面。
- 图片重处理工作并发从 2 降至 1，等待上限仍为 4。原先单个解码预算最高 64 MiB，双解码仅这一项就可能超过 100 MB。串行化降低同时解码峰值，**不等于总进程内存已达标**，也不包含所有编码输入和 WebView 图片内存。
- 补充 100 次快速封面切换、超时、失败、双槽收尾和卸载测试，以及跨线程重图片任务不重叠的 Rust 测试。
- 更新因界面演进而失效的测试：当前/记忆曲目共享 music-pane；普通时间文本替代 RollingNumber；透明播放按钮；明确设置正常动画；同一连接复用播放模式；唯一选择器定位会话名称。保留原有行为断言，不用放宽超时掩盖问题。

### P2：降低 WebView2 常驻成本（待实施与对照验证）

首轮主进程仅约 10 MB 私有工作集，WebView2 的 GPU、browser、renderer 是主要开销。因此优先做可独立回退的实验：

1. 对空白透明 WebView、仅紧凑岛、播放频谱、展开、Studio、多窗口逐层量化基础成本。
2. 检查图片缓存是否保留原图、预加载器、双槽和 Canvas 的重复像素；在不降低当前最大显示尺寸清晰度的前提下按显示尺寸派生缓存。
3. 大图读入在入场控制后执行；识别持有编码输入等待的任务，减少排队字节而不仅限制线程数。保持当前输入格式和失败回退。
4. 控制非可见页面的存活与图片表面；关闭辅助窗口后验证 renderer 和 GPU 私有提交能回落，不能只隐藏窗口。
5. 在支持的 WebView2 API 范围内验证低内存策略。不要默认禁用 GPU、关闭动画、降低 DPI 或强制工作集修剪；这些可能损害体验或只是把驻留页换出。
6. 每项实验必须有相同二进制输入、同场景 A/B 数据。没有测得收益就不合入默认路径。

### P3：100 MB 硬上限的架构决策（待数据决策）

如果空白透明 WebView 的基础运行成本已使严格目标不可达，仅做 Svelte/缓存微调不能保证整程序低于 100 MB。需要评估原生绘制的主岛、动画及播放器，并建立当前功能清单逐项对齐。仓库文档指向独立 native 仓库，可作为候选调查对象，不能假定其功能完整或直接替换。

混合方案（原生紧凑岛、展开时创建 WebView）可能降低日常常驻，但展开时仍可能超过预算，不满足“所有场景低于 100 MB”的严格目标。完整原生方案的迁移范围包括媒体控制、拖动进度、封面/像素化/MV、设置兼容、音量设备、天气时钟、计时器、托盘、多屏/DPI、捕获隐藏、键盘和减少动画支持。迁移前必须先完成功能和动画一致性原型，不能先删除当前功能。

### P4：长稳与发布门禁（待完成）

正式矩阵跑完后执行 8 小时播放、1000 次切歌、300 次展开收起、100 次辅助窗口开关和 20 次音频设备切换；检查内存趋势、句柄/线程增长、晚到 IPC 和窗口关闭后的后台任务。故障注入包括断网、损坏封面、播放器关闭、CDP 不可用、设置写失败。所有数据和未覆盖项目列入报告。

## 4. 详细测试矩阵

| 范围 | 本轮自动化重点 | 后续真实环境验收 |
| --- | --- | --- |
| 形态与动画 | 四边附着、缩放、反向切换、Hover、中途改变布局、减少动画 | 不同刷新率、显卡、DPI、显示器热插拔、实际呈现帧 |
| 媒体 | 播放模式、收藏重试、拖动/键盘 Seek、失败回滚、版本戳去重和旧事件隔离 | 网易云/Spotify/其他实际播放器与兼容版本 |
| 封面 | 快速切换、迟到回调、加载失败/超时、Canvas 100 次卸载、高清开关 | 大图、超大图、损坏图、真实网络和长期缓存 |
| 后台任务 | 隐藏后停止计时/天气/取色/MV/唱片旋转；卸载后无晚到作用 | 截图、录屏、全屏、屏幕共享、休眠恢复 |
| 多窗口 | 浮窗媒体握手、重复打开、关闭/重开、Studio 可见区域轮询 | 反复开关后的整个进程树和 GPU 回落 |
| 系统 | Rust 交互区域、窗口创建互斥、设置原子写和恢复 | 穿透、置顶、托盘、开机启动、多屏坐标 |
| 工具 | 音量拖动/取消、计时绝对截止时间、隐藏后完成一次、时钟分钟边界 | 实际音频设备、城市天气、系统时区变化 |

Playwright 的原生 IPC 多为模拟，不能把夹具通过描述为真实播放器、Win32 输入和多屏集成全部通过。按用户要求，后续测试不使用 computer use。

## 5. 复现命令

```powershell
npm test
npm run check
npm run test:ui
npm run build
cargo test --lib --manifest-path src-tauri/Cargo.toml
cargo build --release --features custom-protocol --manifest-path src-tauri/Cargo.toml
node --test scripts/check-memory-budget.test.mjs
# 先启动 Release，填入该程序的真实 PID：
./scripts/measure-native.ps1 -RootPid <PID> -WarmupSeconds 300 -Seconds 600 -Label release-scene
node scripts/check-memory-budget.mjs dist/performance/release-scene.json dist/performance/release-scene-summary.json
npm run perf:build -- audit-after
npm run perf:fixture -- audit-after
npm run perf:retained -- audit-after
```

内存门禁退出码：0 为本采样场景通过，1 为超标，2 为证据无效或输入错误。它不替代未运行场景的验收。最终结果见同目录 `PERFORMANCE_TEST_REPORT_2026-10-24.md`。
